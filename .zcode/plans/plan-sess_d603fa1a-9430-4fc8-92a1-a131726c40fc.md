# Rung 5 — the direct bind, amended by the preflight (note 21)

Supersedes the earlier draft ("the readback's death"). Note 21 endorsed the
mechanism and corrected the premise: at the measured baseline (12.79 s warm,
min-of-3, glyph3d-js via `--repo-scan-only`), readback is ~25 % (3.2–3.3 s) and
the host record handling is 65–75 % — `convert` 5.4–8.4 s (unstable, not
root-caused) + `compact` 1.5–1.7 s. The GPU chain already beats the engine's
compute (0.29 s warm dispatch vs 0.42 s engine lanes); the ENTIRE gap to
mojo-direct's 1.088 s is record-stream overhead. The phases line landed in
`1769ba8` is the yardstick: re-baseline after each rung, min-of-3, spread
reported, and watch `convert` vanish rather than trusting totals. Preflight
commits `568d224` (tail-pad fix — prerequisite for the survivor scan),
`1769ba8` (phases), `b70bbc0` (chunk fence) are done and mutation-proven;
HEAD `9861d01`, 16 gates, 38 mutations, floor 115.

## Grounding facts the design rests on

- `GlyphInstance` is 48 B, encase==bytemuck (test-pinned); the shader reads it
  as storage binding 1 with chunk-local `instance_index`.
- `GlyphArena` already has the device-resident form: `MappedArena` (Metal
  shared-storage via wgpu-hal), the `uninit_tail`/`commit` protocol,
  range-chunked binding over one buffer, host reads through the pointer
  (seg_tint, diff_backends — unchanged consumers).
- cubecl→wgpu extraction is public and proven (`get_resource::<WgpuServer>` →
  `WgpuResource { buffer, offset, size }`; note 16 phase 0: 0 bad lanes). The
  reverse import has NO API — the pack kernel writes a cubecl buffer and the
  hop consumes it.
- Repo items carry `Paint::PerRecord` (colorize_leaders, indexed by record)
  and `group_id = file index`. Extents are all min/max (order-free → atomics
  bit-deterministic); the only arithmetic is `x + advance` (pure add) and
  `y ± height*0.5` (power-of-two multiply is exact, so fma contraction rounds
  identically) — the device reproduces `compact_records_into` bitwise.
- Survivors ≈ 95.2 M of 96.9 M records → the instance stream is 4.57 GB,
  BIGGER than the 2.89 GB record stream. Unchunked, alongside the mapped
  arena, it would brush the 16 GB ceiling whose failure mode is silently-dead
  dispatches. The pack window reuses the `GLYPH_RECORD_CHUNK` pattern (env
  units = elements per window; defaults 512 MB / element size — 11.17 M
  slots for instances, 16.77 M for records), and each commit message carries
  the peak-memory arithmetic.
- The window base must NOT be `#[comptime]`: six windows cost ~3.5 s cold JIT
  today. It goes in a **1-element params buffer** (`&[u32]`) — note 21's
  prescription, and the investigation confirms it sidesteps every recorded
  hazard: buffer args bind positionally and type-blind, while scalars ride
  the info-buffer region where the one never-root-caused misbind (rank_step:
  TWO trailing runtime u32s) and a real thread-local `InfoBuilder`
  contamination vector live. Green single-trailing-scalar precedents exist
  (`decode`, `cluster_mark`), but the buffer is the form with nothing to
  find out the hard way. One compile, all windows.
- `run_repo_chain` already takes `Option<&GpuContext>`; the renderer's ctx
  exists before repo load. ONE shared driver stays the contract: repo_check
  and CubeclLayout keep calling the same `run_repo_chain`, now with a mode
  (`Records | Instances | Both`) — a second driver would orphan the fence.
- The walk timer at repo.rs:495-496 spans nothing (`t0`/`elapsed` with no work
  between; the walk is pre-done by the caller) — fix where the walk happens.

## The new tail (kernels)

1. **Survivor + leader count pass** — a small integer two-level scan (tile
   partials → spine → apply-style chase), a SEPARATE pass per note 13 (never a
   second counter in the proven monoid). Produces per-leader survivor ordinals
   AND per-item leader + survivor totals; the totals read back tiny
   (item_count-sized), `rec_base` and `slot_base` become host prefix sums over
   that readback — the serial CPU leader scan (`prep`, 0.195 s, the last
   serial O(bytes) host pass) dies in every mode. Slots are scan-ordered,
   never atomic: instance order must stay deterministic because repo-verify
   diffs instance bytes.
2. **Pack kernel** — thread-per-byte like `emit_records`, writes 12 u32 lanes
   per survivor at `slot_base[it] + survivor_ordinal[b]`: pos/gi/row/col from
   existing lanes, `color = colors[rec_base[it] + wc[b]]` (per-record colors
   upload, ~388 MB ≈ 80 ms — the u8 palette stays a later measured commit),
   `group_id` from a per-item table, advance/height pass-through, flags=0,
   _pad=0, window base from the params buffer. Extents in the same kernel via
   per-item atomic min/max on order-encoded floats (the `resolve_x` rmax/xmax
   pattern), seeded like the host loop (page lanes 0.0 over ALL records, ink
   lanes ±inf over survivors). The extent/total lanes read back
   item_count-sized — that IS the placements.

## The hops (one tail, three consumers)

- **Records mode** (check/verify): today's `emit_records` + readback, unchanged.
- **Instance readback hop** (all platforms, 5b): read each packed window and
  memcpy into `arena.uninit_tail(n)` + `commit` — kills `convert` and
  `compact` everywhere; the readback span itself still stalls (hop 3 kills it).
- **Device-copy hop** (Metal, 5c): with the mapped arena present, per window —
  `get_resource` on the chunk handle (the flush IS the handoff), one encoder
  `copy_buffer_to_buffer` into the mapped arena at `first*48`, in-order on the
  shared queue; one final `device.poll` before staging reads the pointer. No
  per-record bytes cross to host.
- **The 5b decision point** (note 21's risk, held explicitly): the instance
  stream at 4.57 GB through the ~0.9 GB/s readback path ≈ 5 s — slower as a
  span than today's record readback, still a large net win once convert+compact
  die. Measure at 5b; then decide before 5c hardens: non-stalling reads/larger
  windows for the readback hop, or the copy hop as the product on every
  platform that can write a device buffer (only seg_tint's host read pins
  non-Metal to readback today).

## The fence follows the path

- `repo_check` runs `Both` and grows tiers beside the existing record
  bit-compare: instance bytes vs the mojo-batched arena (byte-equal) and
  placements vs engine placements (`bit_eq`). Empty-extent edge (blanks-only
  items) must reproduce the host's ±inf seeds.
- The chunked fork pass extends to the instance window (small
  `GLYPH_RECORD_CHUNK` forcing multiple instance windows; the existing PASS
  line texts and `ALL PASS` stay grep-stable).
- New mutations, each with `rebuild`: `survivor-ordinal-zeroed` (instance
  mismatch), `ink-extent-blank-inclusive` (placement bit_eq fails),
  `color-lane-dropped` (instance mismatch), and an instance-window-offset
  sibling of `emitter-window-offset-dropped` for the pack window. Tests +
  `test_floor` bump in the same commit.
- Accounting follows the work: when emission moves device-side, restate the
  `ChainPhases` doc ("chain_dur includes the emit loop") and print_stats'
  `accounted`/`unattributed` sum so the new spans are named, not absorbed.

## Standing rules (note 21, restated)

One logical change per commit; battery green before landing; every perf claim
carries parity + timing in the same run; goldens byte-equal or the change is a
defect; min-of-3 with spread; peak arithmetic in the commit message; the JS
oracle never moves; Mojo exits in ONE cut at rung 6, after repo_check's
reference re-points at `fold::run_pipeline`.

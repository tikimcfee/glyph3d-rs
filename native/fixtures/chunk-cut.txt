chunk-cut.txt: hyper-oracle's input for HyperLayout's intra-line chunk cuts (C15, 2026-10-09).
Line 148 is one line of ~256 KB with no newline: HyperLayout cuts it inside the line, before an ASCII byte,
about every 64 KiB. At each 64 KiB target the byte is inside a cluster sequence (a ZWJ family, a keycap, a flag),
which a cut at a mere codepoint boundary would split; the segment before each target holds non-ASCII advances,
so the next chunk's seed must be the running f32 segment sum; and a continuation segment of emoji is wider than
any ASCII one, so the page stride depends on measuring continued lines. The short lines put the long line past
row 128, the first page, where the stride reaches its glyphs. IMMUTABLE: edit it and the gate silently weakens.

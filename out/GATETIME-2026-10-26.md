# Where verification time goes (2026-10-26, branch `mp-gatetime`)

The goal (Ivan's): the check an agent runs after each change should finish in
under a minute, and lose nothing the gates prove. The full merge-time suite
may take longer, but should shrink too. This note records what was measured,
what changed, and what the figures were after. It is dated; the TIME lines
the runner prints now are the live figures.

Host: the 32-core Linux box (vulkan-nvidia), in this worktree's own
`target/`. Sibling agents were building at the same time, so the load
average was 5 to 35. Treat every figure as ±20 %.

- **Compile versus run.** On an edit the rustc share is products 19 s, test
  compile 15.5 s, clippy 3.1 s, doc 2.9 s and no-ui 1.7 s: five
  configurations of the renderer crate. orphans is not a compile. It is
  cargo-modules loading the workspace the way rust-analyzer does, once for
  each of its 9 targets, on every run, edit or not.
- **The GPU gates** (cargo-test's integration binaries, pick-oracle,
  hyper-oracle, pixel-ab) took about 14 s together, plus cargo-test's GPU
  binaries. They are the four that fail with Vulkan hidden
  (`VK_ICD_FILENAMES=/nonexistent`); repo-verify and reference-port pass
  without a device.
- **cargo-test's run** was serial across binaries. The renderer's unit-test
  binary took 13.5 s, and 10.8 s of that was one test,
  `hyper_oracle::tests::tab_stops_agree_on_every_tier`. The eight GPU
  integration binaries took 1 to 4 s each, run one after another.
  Doctests (zero of them) took about 10 s more, because rustdoc
  `--test` resolves the renderer crate.

## 2. What changed

One commit each, in order:

1. **Scratch per checkout**, under `target/glyph-scratch/`.
2. **The renderer product builds the test binaries too**, with
   `cargo build --release --lib --bins --tests`. One cargo compiles the
   crate and its `cfg(test)` twin side by side: 22 s, against 17 + 15 s
   one after the other. The units are the same: after it, `cargo build
   --release` and `cargo test --release --no-run` both report fresh.
3. **One test build serves two gates** (`glyph/src/test_build.rs`, which
   reads `cargo test --no-run --message-format=json`).
   - **cargo-test**: the runner now runs the harness binaries itself. Each
     runs from its package directory with `CARGO_MANIFEST_DIR` set, and all
     run at once together with `cargo test --doc`. The test-result lines
     and the floor are unchanged. A failing binary no longer stops the ones
     after it, and a binary that reports no result is red, by name.
   - **orphans**: the gate reads rustc's dep-info for every unit of that
     build. cargo-modules is gone from the gate and from `pixi run setup`.
     This also covers the renderer's bin, which cargo-modules could not.
4. **The gates run at once** (`glyph/src/schedule.rs`).
   - Each gate is a child `glyph gate`. Its block is printed in
     build.toml order as it finishes.
   - A gate waits only for an earlier gate that provides an artifact it
     `needs`. `gpu = true` gates run one at a time, and cargo's lock
     orders the cargo gates.
   - Children are spawned from a hard link of the runner. The workspace
     build and the `-p glyph` build re-point `target/release/glyph` (the
     inode changes, measured), and cargo-build now runs while children are
     being spawned.
   - **Every gate declares `tier`.** `glyph test --inner` skips the merge
     tier (cargo-build, cargo-check-no-ui, cargo-clippy, cargo-doc), names
     each gate it skipped, and its verdict says it is not a landing run.
     A full `glyph test` runs every tier.
5. **`tab_stops_agree_on_every_tier`**: its 24 independent cases run on
   rayon. 10.8 s became 2.7 s; the assertions are the same.
6. **`prove --since`**:
   - Prose and scheduling fields (`compare`, `blind_to`, `why`, `scope`,
     `tier`, `gpu`) no longer count as an edited declaration.
   - A mutation is also selected when a changed file holds its `expect`
     (its witness changed).
   - On this branch against main: 116 selected became 29 at that commit (30 at the branch head).
7. **A red gate keeps its whole output** under
   `target/glyph-scratch/kept/`, and the path is printed. That covers the
   child gate's output, each failing test binary's (whose panic message
   cargo-test used to drop), each failing command's, and a diverging
   pixel-ab frame.

## 3. After

Measured at the branch head, one-line edit in `native/src/lib.rs`, load
about 17 to 19:

| | serial (before) | after |
|---|---|---|
| full `glyph test`, one-line edit | 111 s | 53 s |
| full `glyph test`, no-op | 95 s | 27 to 41 s (six runs) |
| `glyph test --inner`, one-line edit | — | 53 s |
| `glyph test --inner`, no-op | — | 30 s |
| cargo-test's run | 29 s | 16 to 19 s |
| a cargo-test mutation's gate (native/src target) | ~50 s (est.) | 36 s |

- **The critical path of an edit run**:
  1. products, 20 to 23 s;
  2. then cargo-test, 16 to 19 s, holding the GPU;
  3. then the other GPU gates, about 14 s (pixel-ab 8 s, pick-oracle
     4 s, hyper-oracle 1.5 s), in turn.

  Everything else fits beside that path, including the merge tier, which
  is why a full run and `--inner` now take the same wall time on this
  host. `--inner` still saves the four merge gates' CPU (clippy, doc and
  the two no-default-features checks each recompile the renderer), which
  matters when siblings share the cores.
- **Prove.** The full unscoped prove was stopped at the coordinator's word
  (Ivan wants no more 40-minute runs). Prove's after-figure comes from the
  provejit branch's relax route. What was measured here:
  - the cargo-test clean-tree check takes 15 s (it was ~30 s);
  - a cargo-test mutation's gate takes 36 s;
  - `--since main` selects 29 of 116 (116 before change 6).
  - Every mutation this branch's changes reach was proven by
    `--mutation`: tests-mod-dropped, tests-silently-ignored,
    hyper-device-page-cols-run, hyper-tab-chunk-rewalk-skipped,
    atlas-pin-moved.

## Not done, and why

- **Picking the scope from `git diff`.** Every scope holds a gate that reads
  `native/src`: cargo-test (rust), hyper-oracle (render) and reference-port
  (corpus). So any Rust change selects all three scopes, and only a
  doc-only diff would shrink. Doing better needs a per-gate `reads`
  declaration, and when one of those is under-declared the gate is silently
  skipped. That is the failure this repo keeps fencing against.
- **GPU gates beside cargo-test.** Serializing them costs the 14 s above.
  Rendering is deterministic, so they would probably pass concurrently, but
  the brief asked for them serialized.
- **A runner change selects only the runner's own mutations in `--since`.**
  An edit to `gates.rs`'s cargo-test or cmd handling can weaken every gate
  of that kind. This branch ran the full prove for that reason. Making
  `glyph/src` select everything is prove's own call (the provejit branch).
- **One full `glyph test` went red, once.** It was the first full run after
  the tab-stop test went parallel, and its output was not kept, so there
  is nothing to read. Since then the runner keeps a red gate's whole output
  (change 7, below). The red has not come back in 27 runs:
  - 13 full runs, 6 of them after a glyph touch that recreates the
    recompile;
  - 12 cargo-test gates, at load 31 to 47;
  - 4 cargo-test gates with a second process looping hyper-oracle on the
    GPU.

  Ruled out, with evidence:
  - shared scratch (now per checkout);
  - fixed paths in the tests (every one is PID-keyed);
  - the parallel tab-stop test (0 failures in 30 runs alone, and 0 in the
    12 contended cargo-test runs);
  - GPU contention from a second process (0 in the 4 runs above).

  Not ruled out: load from sibling worktrees at that moment, which no
  runner here serializes. The next occurrence will be readable under
  `target/glyph-scratch/kept/`.

# Differential Fidelity & Flood Throughput: `glyph-vt` vs `g3d-termd` (2026-11-26)

Differential verification of `crates/glyph-vt` against `g3d-termd/0.1.0` (`libghostty-vt/1.0.1`) across real interactive CLI/TUI programs, Unicode/tab/SGR edge specimens, mid-stream resizes (`80×24 → 132×40 → 60×20`), mid-session `REPAINT`-only subscriptions, and 20 MB flood streams.

## 1. Harness & Scratch-Daemon Isolation

- **Entry point**: [vt-diff.sh](../../tools/vt-diff.sh) invokes [vt_diff.rs](../../crates/termd-client/examples/vt_diff.rs) using the new `TermdHandle::capture` wire request in [client.rs](../../crates/termd-client/src/client.rs) / [msg.rs](../../crates/termd-client/src/msg.rs).
- **Isolation**: `vt-diff.sh` creates `D=/tmp/g3d-vt-$$` (`0700`), exports `G3D_TERMD_DIR=$D` and `G3D_TERMD_ENV_SOURCE=daemon`, connects solely to namespace `probe`, runs an isolated `tmux -L vt-diff-$$ -f /dev/null` socket for the `tmux` scenario, and installs an `EXIT INT TERM` trap that runs `g3d --ns probe stop`, kills the scratch `tmux` server, and `rm -rf "$D"`. Live namespaces (`wall`, `agents`, `default`, `rs-wall`) and `~/localdev/viz-web/glyph3d-js` are untouched.
- **Four comparison oracles at every settled quiet point** (after verifying `subscriber_seq == terminal.seq` via `client.list()`):
  1. **`capture(Plain, unwrap: false)` vs `Vt` row text**: compares `termd`'s `libghostty-vt` plain row capture line-for-line against `Vt`'s resolved screen rows.
  2. **`capture(Plain, unwrap: true)` vs `Vt::text(0, 0, cols, rows - 1)`**: verifies soft-wrap (`Row::wrapped`) vs hard-newline joins across the entire active grid.
  3. **Mid-session `REPAINT`-only subscriber (`Role::Watch`)**: opens a fresh `subscribe` at the quiet point (receiving only `termd`'s `REPAINT` + state events, zero prior `OUTPUT` history), feeds that `REPAINT` into a fresh `Vt`, and compares every cell (`content`/grapheme cluster, `width`, `fg`, `bg`, `ul`, `attrs`), `wrapped` row flags, `cursor` (`col`, `row`, `visible`, `shape`, `blink`), `cursor_color` (`OSC 12`), `default_fg`/`default_bg`, `modes`, and `title` against the live `Vt`.
  4. **`Event::Modes` vs `Vt` `modes`**: checks `alt_screen`, mouse tracking, `SGR` mouse, `bracketed_paste`, `app_cursor`, and `focus_events`.

## 4. Flood Throughput (`120×40` Grid, `64 KiB` Read Chunks, 20.0 MB Streams)

Measured on `laptop-2` (Apple M2, `release` profile, host load avg `~5.5`):

| Stream (20.0 MB) | Line / Escape Structure | `Vt::feed + fill @ 60 Hz` (CPU) | `% feed` / `% fill` (`@ 60 Hz`) | `Vt::feed + fill` per `64 KiB` | Whole-Pass Wall `@ 60 Hz` | Live `PTY → termd → socket → Vt @ 60 Hz` |
| :--- | :--- | ---: | :---: | ---: | ---: | ---: |
| **`yes` (`"y\r\n"` × 6.67M)** | 3 B/line (`6,666,667` full-screen scrolls) | **30.8 MB/s** (`10.3M` lines/s) | `99.9%` / `0.1%` (39 fills) | **28.7 MB/s** | 8.2 MB/s | **4.4 MB/s** (20.0 / 20.0 MB) |
| **`cat` 20 MB source** | ~50 B/line Rust source (`~400k` scrolls) | **164.8 MB/s** | `99.9%` / `0.1%` (8 fills) | **113.4 MB/s** | 10.8 MB/s | **9.8 MB/s** (20.0 / 20.0 MB) |
| **Colour-heavy 20 MB** | ~165 B/line (`SGR 38;2`, `38;5`, `4:3`, `58;5`, `7` per line; `~121k` scrolls) | **86.3 MB/s** | `99.9%` / `0.1%` (14 fills) | **97.4 MB/s** | 22.7 MB/s | **1.7–4.5 MB/s** (20.0 / 20.0 MB) |

*(Microbenchmark cross-check via `cargo run --release -p glyph-vt --example vt_bench`: `feed/plain_ascii` `123.3 MB/s`, `feed/sgr_heavy` `162.1 MB/s`, `feed/fullscreen_redraw` `72.0 MB/s`; `fill/unchanged` `4 ns`, `fill/one_row` `0.67 µs`, `fill/full` `14.38 µs`.)*

### Where the Time Goes

1. **Frame-paced `Vt::fill` is negligible (`0.1%` of CPU at 60 Hz)**:
   - A full `120×40` `Vt::fill` takes `~14.4 µs` (`0.67 µs` when one row is dirty, `4 ns` when clean). Across a 20 MB flood taking `120–650 ms` of CPU, 60 Hz frame pacing invokes `fill()` `8–39` times (`0.1–0.6 ms` total). Even calling `fill()` unconditionally after every `64 KiB` read (`306` calls = `~4.4 ms`) leaves `feed()` responsible for `>95%` of CPU time.
2. **Scroll density explains the `5.3×` MB/s difference between `cat` (`164.8 MB/s`) and `yes` (`30.8 MB/s`)**:
   - `cat 20 MB source` spends most bytes inside `Stream::process` → `Terminal::print_ascii_slice` (`~6 ns/B`) with one scroll every ~50 bytes (`~400k` scrolls).
   - `yes` (`"y\r\n"`) triggers a full-screen `Screen::scroll_up(1)` every **3 bytes** (`6,666,667` scrolls in 20 MB = **`97 ns` per line + scroll**, or **`10.3 million lines/s`**).
   - During this task, three cheap hot-path improvements were landed in [page.rs](../../crates/glyph-vt/src/term/page.rs), [screen.rs](../../crates/glyph-vt/src/term/screen.rs), and [stream.rs](../../crates/glyph-vt/src/term/stream.rs):
     - `Row::clear` retains `Vec<Cell>` capacity and skips cell writes when `bg_color == StyleColor::None` (`cells.clear()`).
     - Full-width non-history `scroll_up` shifts `active` via a single `slice::rotate_left(count)` (`memmove` of `40 × 32 B = 1,280 B` `Row` headers) and skips re-marking all 40 rows dirty on every `\n` because `pending_scroll.scrolled_top > 0` already forces full-grid resolution on the next `fill()`. (Across 6.67M scrolls, that remaining `1,280 B` header `memmove` accounts for `8.5 GB` of L1 traffic; a ring-indexed `active` array could remove it if `>10M lines/s` is ever needed.)
     - `Stream::process` dispatches ground-state `\r` and `\n` (and `\r\n` pairs) directly to `Terminal::execute` without routing through `Utf8Decoder`.
3. **CSI parameter parsing dominates colour-heavy floods (`86–97 MB/s`)**:
   - Roughly half the bytes in `colour-heavy` are `CSI` SGR sequences (`38;2;r;g;b`, colon subparameters `4:3`, `58;5;p`), which exit `print_ascii_slice` on `ESC` (`0x1b`) and step byte-by-byte through `Parser::step` (`CsiParam` digit/separator accumulation) and `Terminal::apply_sgr`.
4. **End-to-end live `PTY + termd` (`1.7–9.8 MB/s`) is bounded by kernel PTY + dual-VT daemon framing, not `glyph-vt`**:
   - Every byte traverses `cat` → macOS kernel PTY (`ONLCR` `\n → \r\n` expansion in small tty buffers) → `g3d-hold` → `g3d-termd` (`libghostty-vt` `vt_write` + `OUTPUT` frame encode with `Role::Own` `flow: "block"` backpressure) → Unix socket → `termd-client` reader thread → `Vt::feed` + 60 Hz `Vt::fill`. Because `glyph-vt` processes the same streams in-process at `31–165 MB/s`, the client-side emulator has `7×–17×` headroom over the PTY + daemon pipe.

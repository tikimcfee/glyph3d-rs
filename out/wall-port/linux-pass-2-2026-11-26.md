### 1.3 Smoke Suite 1: `tools/wall-smoke.sh` (20 Checks) on Wayland and X11
- **Baseline run uncovered a real Linux Wayland window bug** on Check 15 (`Shift, CapsLock, dead & IME`):
  - On X11, `wall-smoke.sh` passed `20/20` on the first run.
  - On Wayland, Check 15 failed (`19/20`): raw `'x'` (`0x78`) leaked to the PTY between `app.ime preedit "´"` and `app.ime commit "é"`.
  - **Root cause:** In `winit 0.30.13`'s Wayland `zwp_text_input_v3` backend (`seat/text_input/mod.rs:118-132` + `window/state.rs:1038-1046`), every `Window::set_ime_cursor_area` call sends `text_input.set_cursor_rectangle(...)` + `text_input.commit()`. When KWin replies with `zwp_text_input_v3.done` and no fresh `preedit_string` is pending, `winit` unconditionally emits `WindowEvent::Ime(Ime::Preedit("", None))`, clearing `App::ime_composing` whenever a terminal cursor move triggers `sync_ime_cursor_area` (or when an earlier cursor-rect `done` arrives asynchronously after `app.ime preedit`).
- **Commits (one per logical fix, window vs. script noted):**
  1. **Window fix (`5169a40`)** — `wall (window): keep Wayland cursor-rect commits from clearing IME preedit` (`native/src/wall/app.rs`): defer `sync_ime_cursor_area` while composition is active, and track `script_ime_composing` (`wallctl app.ime`) separately from `winit`'s `WindowEvent::Ime` state so in-flight Wayland `done` replies cannot clobber scripted preedit.
  2. **Window addition (`49ad880`)** — `wall (window): report active platform chord set in app.where` (`native/src/wall/script.rs`, `native/src/wall/app.rs`): `app.where` now emits `platform other chord=ctrl+alt copy=ctrl+shift+c paste=ctrl+shift+v ctrl_click_menu=false` on Linux (`platform mac chord=cmd copy=cmd+c paste=cmd+v ctrl_click_menu=true` on macOS); unit-tested for both platforms in `wall::script::tests`.
  3. **Script fix (`227e870`)** — `tools/wall-smoke (script): query chord set from app.where` (`tools/wall-smoke.sh`): queries `CHORD`, `COPY_CHORD`, `PASTE_CHORD`, and `CTRL_CLICK_MENU` from the running wall's `app.where` instead of `uname -s`, holds the queried chord modifier keys in Check 20, and prints active chord names (`ctrl+alt+backslash`, `ctrl+alt+d / ctrl+alt+shift+d`, `held ctrl+alt`).

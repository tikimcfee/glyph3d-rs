# The wall in glyph3d-rs: plan (2026-11-26)

The wall is an infinite canvas of live terminals. It exists today as a browser app
(`wall/` in glyph3d-js). This is the plan for building it natively here. It is the
working document of a long run: keep it current, and say in a commit when a decision
in it changes.

## The goal (Ivan, 2026-11-26)

A Rust-native, 3D-based infinite canvas of terminals that replaces the browser app,
with no relay, tokens or HTTP: the app on macOS or Linux talks straight to the
terminal daemon (`g3d-termd`, over its Unix socket) and to gomuxai (`agent`). Running
on the M2 first. **Done for this run: Ivan types "well hello there!" into a terminal
in the new UI.** Everything after that he drives from behaviour reports.

## Decisions

- **Off makepad for UI; relax stays as the JIT; the rest is ours** (Ivan, 2026-11-26).
  The app is winit + wgpu in `native/`. Nothing new goes in `makepad/src`. The makepad
  host stays in the tree untouched; deleting it is Ivan's call.
- **Terminals are objects in the glyph3d scene**, drawn by our own cell pass under an
  orthographic camera. Not 2D widget text. A terminal must be able to stand in a 3D
  scene later.
- **Flat panels are egui** (palette, sidebar, settings, status, help): the equivalent
  of the browser's DOM chrome. Everything on the canvas (title bars, frames, labels,
  selection, grid paper) is ours.
- **Fonts are ours**: a Rust Slug encoder and fonts loaded at run time (`glyph-font`).
  The prebaked atlas (`assets/atlas/`) stays as it is for code scenes and is the
  wall's first glyph source, so no font work blocks the first terminal.
- **The emulator** is makepad's pure-Rust port of Ghostty's VT core
  (`makepad/apps/terminal/src/term`, MIT), vendored as `crates/glyph-vt` behind one
  seam. Upstream libghostty-vt is the alternative if the port proves behind. termd's
  planned packed cells would replace a client emulator altogether, later.
- **We use our own termd**, to find its warts. glyph3d-js stays read-only for this
  run; a termd defect is written down (below, "termd findings"), not patched there.
- **Checks are for "did it blow up?"** (Ivan, 2026-11-26). No golden adoption, no
  stepwise gate run per change. Each crate has its own tests; `cargo glyph test
  --inner` is run at milestones. Ivan tests behaviour at the M2.
- **Many agy agents, on targeted tasks.** The lead (Claude) owns the seams, the
  integration and what runs on Ivan's screen.

## The pieces and their seams

```
 g3d-termd ──socket──> termd-client ──bytes──> glyph-vt ──Screen──> cell renderer ──> wgpu
     ^                      |                                           ^
     └── key/paste/mouse ───┘        wall-core (layout, groups,         │
                                      splits, keys, verbs, store) ──────┤
                                      glyph-font (runtime atlas) ───────┘
```

Each piece is a crate under `crates/` with no window and no GPU, except the renderer
and the app, which live in `native/src/wall/`.

### `crates/term-cells` (done, lead)

The screen as plain data: `Cell { content, fg, bg, ul, attrs, width }`, `Screen {
cols, rows, cells, row_gen, wrapped, generation, cursor, modes, title, clusters,
default_fg, default_bg }`. Colours are final sRGB (red in the low byte); inverse and
conceal are already applied; the attribute bits are `core/cellAttrs.js`'s. Read its
source: it is the contract between B and D.

### A. `crates/termd-client`

A client for protocol 1.5, std + serde/serde_json only, edition 2021.

```rust
pub struct Target { /* a namespace, or an explicit socket path */ }
pub struct Termd { /* one connection; owns a reader thread */ }
impl Termd {
    /// Connect; start `g3d-termd --ns <ns> --daemon` if nothing listens, then retry.
    pub fn connect_or_start(target: &Target, client_name: &str, wake: Box<dyn Fn() + Send>) -> Result<Termd, Error>;
    /// Requests block the CALLER only until their reply, never the reader thread.
    pub fn list(&self) -> Result<Vec<TermInfo>, Error>;
    pub fn create(&self, opts: &Create) -> Result<TermInfo, Error>;
    pub fn subscribe(&self, id: &str, role: Role, size: Option<(u16, u16)>, history_rows: u32) -> Result<Subscription, Error>;
    pub fn resize(&self, handle: u32, cols: u16, rows: u16) -> Result<(), Error>;
    pub fn key(&self, handle: u32, key: &Key) -> Result<(), Error>;
    pub fn paste(&self, handle: u32, text: &str) -> Result<(), Error>;   // chunked past a frame
    pub fn mouse(&self, handle: u32, ev: &Mouse) -> Result<(), Error>;
    pub fn input(&self, handle: u32, bytes: &[u8]) -> Result<(), Error>; // raw INPUT
    pub fn view(&self, handle: u32, v: View) -> Result<ViewReply, Error>;
    pub fn repaint(&self, handle: u32) -> Result<(), Error>;
    pub fn kill(&self, id: &str) -> Result<(), Error>;
    /// Everything the daemon sends that is not a reply, in order.
    pub fn events(&self) -> &std::sync::mpsc::Receiver<Event>;
}
pub enum Event {
    Output { handle: u32, seq: u64, bytes: Vec<u8> },
    Repaint { handle: u32, seq: u64, cols: u16, rows: u16, view: bool, bytes: Vec<u8> },
    Size { handle: u32, cols: u16, rows: u16 }, Title { handle: u32, title: String },
    Modes { .. }, Bell { handle: u32 }, Lagged { handle: u32 }, Exit { .. }, Closed { handle: u32 },
    Status(serde_json::Value), Disconnected { restart: bool, message: String },
}
```

`wake` is called on the reader thread each time an event is queued (the app wakes its
event loop with it). The client rides a daemon restart (`ERROR restart`: reconnect,
re-subscribe, ask for a repaint). Tests run against the real `g3d-termd` in a scratch
namespace (below).

### B. `crates/glyph-vt`

```rust
pub struct Vt { /* the emulator */ }
impl Vt {
    pub fn new(cols: u16, rows: u16, theme: &Theme) -> Vt;
    /// A terminal's bytes, in order. Frame boundaries mean nothing.
    pub fn feed(&mut self, bytes: &[u8]);
    pub fn resize(&mut self, cols: u16, rows: u16);
    /// Bring `screen` up to date, rewriting only the rows that changed since
    /// this Vt last filled it; returns whether anything changed.
    pub fn fill(&mut self, screen: &mut term_cells::Screen) -> bool;
    /// Text of a cell range (selection, copy).
    pub fn text(&self, ..) -> String;
}
```

termd answers the program's queries itself, so the emulator's own replies are
dropped, never sent. Known gaps in the port, from the 2026-11-23 review: its reply
buffer grows unbounded if never drained, soft reset (`CSI ! p`, which every REPAINT
begins with) misses some state, and it tracks one dirty flag, not rows.

### C. `crates/glyph-font`

Fonts at run time, in the engine's Slug format, so the engine's coverage shader
draws them unchanged:

- a font file (TrueType `glyf` and CFF, variable instances by axis) to quadratic
  curves normalised to the CELL (`assets/atlas/FORMAT.md`: x over the advance, y from
  descender to ascender, u16-packed, two texels a curve);
- a growable atlas: `glyph(family, face, content) -> slot`, encoding on first use,
  with the texels that changed since the last frame handed out for upload;
- the cell and line metrics of a family (advance, ascender, descender, underline and
  strikethrough position and thickness);
- box drawing, blocks, braille and powerline generated to the cell
  (`shaping/cellSprites.js` is the spec).

Its oracle: encode `Cousine-Regular.ttf` (vendored at
`tools/vendor/ref/packages/glyph3d-core/src/fonts/`) and compare against the baked
atlas's curves for the same glyphs.

### D. The cell renderer and the app, `native/src/wall/`

- A cell pass (wgpu): one small instance buffer per terminal, position derived from
  the cell's index, drawn as fill, then ink (the Slug coverage of
  `glyph_field_derived.wgsl`, with `abs(coverage)`), then lines and cursor. A
  terminal is a rectangle in world space at a depth; the camera is orthographic.
- The app (winit): a window, the camera (pan, zoom about the pointer), terminals
  from termd in namespace `rs-wall`, keys to the focused one, render on demand.
- `--wall` opens it. `--wall-replay FILE --screenshot OUT.png` draws a recorded
  terminal byte stream offscreen with no daemon: how an agent checks its own pixels.

### E. `crates/wall-core`

The wall's rules with no window: rects and hit tests, flow and tiling, groups, the
split tree, snapping, z-order, scroll, the chord table, the verbs, the context-menu
policy, label placement, the settings schema, the store. Each is a port of one JS
module with its `tools/wall-*.test.mjs` as the spec, ported as Rust tests.

## Milestones

1. **Hello.** `glyph3d-native --wall` opens a window with one live shell from termd;
   typing works; the screen follows output. Glyphs from the prebaked atlas.
2. **The canvas.** Pan and zoom, several terminals, spawn, close, move, resize (as
   the size's owner), focus, z-order, title bars, grid paper, state saved to a file.
3. **Text.** Run-time fonts (Monaspace Neon, four faces), sprites, style lines,
   selection and clipboard, mouse reporting, scrollback.
4. **Structure.** Groups, tiles, splits, fullscreen, snap.
5. **Chrome.** egui panels and the `wall.*` verbs, reachable from a CLI.
6. **Agents.** gomuxai's agents listed and attached; Agent View.
7. **Default.** The app with no arguments opens the wall.

## Rules for everyone working on this

- **Never touch termd namespaces `wall`, `agents` or `default`.** Ivan's live
  terminals and agents are in them. Tests and experiments use a scratch daemon:
  `G3D_TERMD_DIR=/tmp/g3d-<something-short>` and a namespace of your own, stopped when
  you finish. The socket path must stay under 100 bytes, so never under `$TMPDIR`.
  The app's own namespace is `rs-wall`.
- **glyph3d-js and makepad are read-only.** Copying MIT/Apache code out with its
  licence and attribution is fine; editing there is not.
- **Work in your own worktree** on a branch from `wall`, commit there, and say what
  you ran in the commit message. Don't push `main`; don't merge into `work`.
- **Stay in your piece.** A seam that doesn't fit is reported to the lead, not
  changed unilaterally: other people are coding against it.
- **Done means it runs.** State what you ran and what it printed. A test that could
  not fail is not a test.
- **New dependencies** are fine when they earn their place (say why in the commit);
  wgpu 30, winit 0.30, glam 0.33 and egui 0.36 are pinned.

## termd findings

Defects and rough edges found in our own daemon while building against it. One line
each: what happened, how to reproduce, where in its source if known.

Found by the termd-client agent, 2026-11-26, from termd's source and its live tests
(paths under glyph3d-js `crates/g3d-termd/src/`). None is confirmed by the lead beyond
reading the report; each needs a look on the termd side.

- **`capture` can send a frame past `max_frame`.** Its size check counts raw bytes
  before JSON escaping (`owner.rs:1636`); a 3 to 15 MiB capture in `"format": "vt"`
  escapes every ESC to six bytes, so the reply exceeds 16 MiB and a compliant client
  drops the connection instead of getting `too_large`.
- **A refused `input_full` write still counts in `in_bps`** (`owner.rs:1990-2000`):
  the counter is bumped before the buffer check.
- **A failed emulator resize answers `ok: true`** (`owner.rs:1439-1442, 1607-1608`):
  no PTY resize, no `size` event, and the caller is told it worked.
- **`resize` sends `EVENT size` before its `REPLY`**, where `take` replies first as
  PROTOCOL.md documents.
- **PROTOCOL.md's request error table omits `input_full`**, which `key` and `mouse`
  return as a reply.
- **A client that asks for a repaint after reconnecting or `lagged` gets two**: the
  daemon already sends one on its own in both cases. Harmless, but the client's
  explicit `repaint` there is redundant.

## Findings in the JS wall

Differences and defects the porting agents found in the JS originals; ported as they
are unless noted.

- `splitTree.dock` accepts a pane id that is not in the tree and inserts it as a new
  leaf instead of throwing.
- `splitTree.fromMembers` never terminates when `columns <= 0` (Rust refuses zero).
- `chord.isChord` on macOS ignores extra Ctrl or Alt, so Cmd+Opt+D still runs the
  Cmd+D verb.
- `chord.isCopyChord` on macOS ignores Shift (Cmd+Shift+C copies).
- `keyEncoding.isPasteChord` does not branch on platform, so Ctrl+Shift+V on macOS and
  Super+V on Linux are dropped instead of reaching the program. The Rust port DOES
  branch (a deliberate difference).
